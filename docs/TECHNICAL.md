# VoltChanger — технические заметки

## Компоненты

Лаунчер в `src/` — Rust с GPUI Kit 0.9.1. Он запускает Dota 2 через Steam,
ожидает процесс и нужные модули, проверяет x64 PE и отсутствие повторной загрузки,
затем подключает нативный модуль. Ожидание можно отменить без завершения игры.

Нативный C++ модуль находится в `upstream/src/`. Имя `ovr_skins.dll`, внутренние
идентификаторы OVR и формат данных сохранены для совместимости. Публичное имя
приложения и EXE — **VoltChanger**.

Каждая конфигурация CMake создаёт отдельный каталог DLL в `build/native/package`.
Путь записывается в `build/native/ovr-dll-path.txt`. Это позволяет собрать новую
версию, пока предыдущий модуль используется игрой. Новая DLL начинает работать
после ручного перезапуска игры; безопасная выгрузка из работающего процесса не реализована.

## Запуск и диагностика

Начиная с 0.2.0 окно оформлено собственным заголовком, голубым glass-фоном и
полупрозрачными панелями поверх встроенной иллюстрации. Для Windows запрашивается
`WindowBackgroundAppearance::Blurred`; доступность размытия зависит от системы.
Оригинальная графика в `resources/launcher` включается в EXE через AssetSource,
а `build.rs` встраивает многоразмерную ICO и сведения о версии через Windows SDK rc.exe.
Для обычной сборки Python и генератор картинок не нужны.

Все переключатели находятся в отдельном экране настроек. Тема и анимации сохраняются
в `%LOCALAPPDATA%/OVR/appearance.json`, не затрагивая инвентарь. Первоначальное состояние
анимаций учитывает настройку Windows. Постоянных декоративных анимаций нет; переходы
однократные, а переключатели используют анимацию GPUI Kit.

`start.cmd` вызывает `start.ps1`, который открывает `VoltChanger.exe --play` рядом
со скриптом либо `dist/VoltChanger/VoltChanger.exe` при запуске из корня проекта.

Лаунчер не запрашивает административные права автоматически. Успешная загрузка
DLL и готовность SDK — разные состояния: инициализация заканчивается записью
`OVR initialization complete`. Даже этот статус не заменяет проверку поведения в игре.

| Данные | Путь |
|---|---|
| Настройки лаунчера | `%LOCALAPPDATA%/OVR/launcher.json` |
| Журнал лаунчера | `%LOCALAPPDATA%/OVR/launcher.log` |
| Предметы и экипировка | `%LOCALAPPDATA%/OVR/cache/inventory.cfg` |
| Резервная копия инвентаря | `%LOCALAPPDATA%/OVR/cache/inventory.cfg.bak` |
| Переключатель сборок | `%LOCALAPPDATA%/OVR/recommended_builds.cfg` |
| Кэш гайдов | `%LOCALAPPDATA%/OVR/cache/dotacoach/` |
| Настройки и журнал DLL | `ovr_*.cfg`, `ovr_skins.log` рядом с модулем |

Личный инвентарь и настройки не публикуются. Переименование приложения не меняет
каталог OVR, чтобы существующие данные продолжили использоваться.

## Инвентарь и ресурсы

Сохраняются полные локальные записи: предметы, слоты, стили и атрибуты.
Запись атомарная, с резервной копией и восстановлением повреждённого основного файла.
Legacy-конфигурация импортируется при первом использовании общего кэша.

Автоматическая выдача всего каталога отключена. Нетронутые неэкипированные записи
прежнего каталога архивируются обратимой миграцией; ручные вещи и экипировка сохраняются.
`cosmetic_catalog.txt` используется для классификации, а не массового создания предметов.

Восстановление инвентаря откладывается до окончания пересборки SO cache, затем
выполняется порциями. Полные входящие подписки не дополняются локальными объектами;
новая подписка отменяет предыдущую очередь восстановления.

Курьеры и эмблемы ограничены своим владельцем. Ландшафт разрешается через нативный
путь ресурсов с выбранным econ view; для смены требуется новая загрузка карты.

## Игровой интерфейс

Исходная сетка героев сохраняется: добавляются подписи к карточкам и собственный
визуальный уровень. Для значков в профилях требуется совпадение с собственным account ID.
XP, награды и серверный прогресс не начисляются.

Локально открытые реплики воспроизводятся через звуковое событие и локальное сообщение
чата; лишний запрос таких реплик на сервер не отправляется. Для обычных доступных
реплик сохраняется исходное игровое действие.

Публичная статистика игроков использует предоставленные клиентом идентификаторы.
Для закрытой истории обхода нет. Статистика по короткой выборке и определение
предполагаемой линии не являются достоверным определением роли или смурф-аккаунта.

## Рекомендованные сборки

Переключатель доступен в лаунчере и настройках игрового помощника. При включении
заменяется содержимое выбранной колонки гайда магазина; при выключении восстанавливается
выбранный обычный гайд. Используются нативные `DOTAShopItem` и иконки способностей.

Источник — публичные страницы DotaCoach `/en/heroes/{slug}/builds/{role}`.
Таблица `dotacoach_heroes.txt` получена из каталога источника по точному `npcName`.
Парсер проверяет героя и роль, извлекает четыре стадии предметов, порядок способностей
и рекомендуемые таланты. Идентификаторы проверяются по метаданным установленной игры.
Неизвестный предмет или неподходящая роль дают ошибку, а не частично подставленный гайд.
Support у источника общий для позиций 4/5. Частоты покупок, которых нет в источнике,
не добавляются. Выбранный талант показывается как рекомендация, без выдуманной пары.

Загрузка и разбор идут в фоновом потоке, запросы сериализованы. Повтор одного
героя/позиции ограничен 30 минутами; успешный ответ сохраняется атомарно. При ошибке
показывается ранее сохранённая сборка с явной пометкой кэша. Dota2ProTracker не запрашивается.

Другие открытые источники: [OpenDota API](https://docs.opendota.com/) и публичные
средние показатели Valve. Пароли, токены Steam и приватная история этим источникам не передаются.

## Сборка и тесты

`build.ps1` готовит закреплённую ревизию протоколов, собирает Protobuf 3.21.12,
генерирует сообщения, собирает модуль со статическим C++ runtime и Rust-приложение.
Удаляются только неподдерживаемые стандартным генератором аннотации Valve;
исходные схемы остаются в `vendor/protos`. Выходной каталог — `dist/VoltChanger`.

Rust-проверки и сборка C++ описаны в [CONTRIBUTING.md](../CONTRIBUTING.md).
CTest покрывает экипировку, конфигурацию, изоляцию кэша, метрики, интерфейсные политики,
прогресс героя, публичные истории и разбор гайдов. Тесты парсеров используют реальные
фактические образцы; они не подставляются пользователю вместо живого ответа.

Дополнительный тест загрузчика использует отдельный дочерний процесс:

```powershell
cmake --build build/native --config Release --target loader_fixture
$env:OVR_TEST_DLL = (Resolve-Path build/native/Release/loader_fixture.dll).Path
cargo test --locked
```

Поведение на текущей версии Dota проверяется отдельно в игре. Подробные ограничения
каждой функции перечислены в [FUNCTIONS.md](../FUNCTIONS.md).
